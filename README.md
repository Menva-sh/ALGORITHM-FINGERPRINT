# Algorithm Selection via Learned Complexity Fingerprints

Given a graph and a source–target query, predict which shortest-path algorithm will be
fastest **without running all of them**, and count the cost of deciding.

```
graph + query -> fingerprint (features) -> selector -> chosen algorithm
```

**Live demo:** https://algorithm-fingerprint.streamlit.app/ (it runs on shared cloud CPUs,
so its live timings are noisier than the benchmark's).

All results quoted anywhere come from `results/` and are summarised in
[`results/summary.md`](results/summary.md), which is generated by a script. This README
deliberately contains no result numbers.

## Problem

Single-pair shortest path on graphs with non-negative weights. Candidates, all written in
plain Python on one shared adjacency-list structure (`src/graph.py`, `src/algorithms.py`):

| Algorithm | Applicable when |
|---|---|
| Dijkstra (binary heap) | always |
| Bidirectional Dijkstra | always |
| A* (Euclidean heuristic, scaled to stay admissible) | graph has coordinates |
| BFS, Bidirectional BFS | graph is unweighted |

The selector only chooses among applicable algorithms. Every algorithm must return the same
path cost; the benchmark stops if they disagree.

## Method

1. **Graphs** (`src/generators.py`): Erdős–Rényi, Barabási–Albert, Watts–Strogatz, 2D grids
   with obstacles, random geometric graphs; 100–5000 nodes; unit, uniform, heavy-tailed and
   (for graphs with coordinates) length-based weights. Every graph has its own seed.
2. **Fingerprints** (`src/fingerprint.py`): four cost tiers. Tier-0 is stored metadata, Tier-1
   is one linear scan, Tier-2 uses samples, and Tier-3 is exact and expensive. Every feature
   function is timed.
3. **Benchmark** (`src/benchmark.py`): per query, warm-up runs, then the median of repeated
   timings of the counter-free version of each algorithm (op counts come from a separate
   counting run). Workers are pinned to P-cores and only time on AC power. The labels are
   the fastest algorithm, the fewest operations, and ties.
4. **Selectors** (`src/models.py`): random forest, RBF-SVM, MLP and a shallow decision tree
   evaluated in plain Python (so its inference cost matches the plain-Python algorithms).
5. **Evaluation** (`src/evaluate.py`): split by graph, never by row. The metrics are accuracy,
   regret, and **net time** (features + inference + chosen search), compared against the best
   fixed algorithm, an oracle, random choice and running every candidate.

## How to reproduce

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt      # Windows; bin/ on Linux/macOS
.venv/Scripts/python -m pytest                                # all stages are tested
.venv/Scripts/python -m src.reproduce                         # every table + figure (~10 min)
.venv/Scripts/python -m streamlit run app/demo.py             # interactive demo
```

`src.reproduce` regenerates `results/` from the committed timing datasets
(`data/dataset.csv`, `data/dataset_large.csv`, `data/dataset_real.csv`, `data/probes*.csv`).
`--from-scratch` also regenerates the graphs and re-times everything. That takes hours and
needs AC power. Set `benchmark.cpus` for your machine first; `python -m src.benchmark
--calibrate` lists the cores. Real graphs: `data/real_graphs/*.edges`; the road network was
fetched with `python -m src.real_graphs --osm "Piedmont, California, USA" --name road_piedmont`
(needs `pip install osmnx`).

## Limitations

- **One language, one machine.** Everything is plain Python on one laptop (Intel Core Ultra 5
  125H, P-cores only). Absolute times and the *size* of the gains will differ in C++/Rust,
  where search is far cheaper relative to interpreter overhead. The second-machine check in
  `labels_ablation` is implemented but was **not run**, because there is no second dataset.
- **Timing noise.** Repeated timings of the same query vary noticeably (see `labels_noise.csv`),
  and labels near a tie can flip between runs. Regret is reported alongside accuracy for this
  reason.
- **Power incident.** Some graphs were first timed partly on battery. They were identified
  from the Windows power log, moved to `data/bench*/battery_run/`, and re-timed on AC; the
  benchmark now pauses on battery. Rows re-timed after the fix carry `ac_power = True`.
  Earlier rows were checked against the power log instead.
- **Synthetic training data.** Five generator families with at most 5000 nodes. The
  large-graph test stops at 20,000 nodes (50,000 was dropped to save benchmark time). Real
  graphs are few and small: 4 SNAP graphs and one 352-node road network. Directed SNAP graphs
  are treated as undirected.
- **Whole-graph features.** Static fingerprints give every query on a graph the same choice.
  Per-query probing helps accuracy but costs more time than it saves at these search sizes.
- **Library overhead.** The sklearn models lose on net time mainly because each
  single-query prediction carries sklearn's call overhead. The deployable selector is the
  plain-Python tree.
- **Approximate conformal guarantee.** Queries from one graph are correlated, so coverage is
  only approximately guaranteed; the empirical coverage is reported.
- **Heavy features skipped on big graphs.** Exact Tier-3 features are not computed for the
  20k-node and real graphs; the experiments there use Tier-0/1 (and probes).
